# LesDaliBI — покрытие полевых работ ПУЛ площадью на дату

- **Дата сессии:** 2026-09-24
- **Репозиторий:** `SexyIdol2003/LesDaliBI`
- **SQL-коммит:** `9eae1ba feat(dwh): add field day work coverage mart`
- **Статус:** витрины созданы, применены в PostgreSQL и проверены QA.

## Цель

Проверить, можно ли связать строки путевых листов тракториста (ПУЛ), зарплату и нормативное ГСМ с экономической площадью поля на дату.

Целью не являлся расчёт полной себестоимости 1 га. Проверялись:

- полнота связи ПУЛ с полем;
- полнота связи подтверждённых полевых строк с экономической площадью на дату;
- корректность единиц измерения работ;
- возможность отдельно показывать гектарные и почасовые показатели;
- исключения, которые нельзя распределять по полям без методики.

## Почему часы нельзя переводить в гектары

Среди 1 536 связанных с полем строк:

| Тип работ | Строк | Рабочий объём | Зарплата | Нормативное ГСМ |
|---|---:|---:|---:|---:|
| Гектарные (`HA`) | 824 | 14 688,12 га | 3 256 044,52 ₽ | 123 590,89 л |
| Почасовые (`HOURS`) | 712 | 1 634,50 ч | 675 450,00 ₽ | 12 075,00 л |

Все 712 строк без гектаров имеют заполненное значение `chasov`:

```text
Строк с часами: 712
Строк с тоннами: 0
Строк с километрами: 0
Строк с моточасами: 0
Строк без измеренного объёма: 0
```

Проверка передачи гектаров от соседних строк показала:

| Проверка для почасовых строк | Результат |
|---|---:|
| В том же документе и поле есть гектарные строки | 384 строк |
| В том же документе и поле нет гектарных строк | 328 строк |
| Совпадение гектарной строки по `документ × поле × операция` | 0 строк |

Поэтому нельзя переносить гектары:

- из другой строки того же документа;
- из другой строки по тому же полю;
- из другой операции;
- из другой техники;
- из среднего по сезону.

Такой перенос был бы расчётной дооценкой без первичной связи.

## Ограничения

1. Витрина содержит только 2026 год.
2. В основную витрину включены только строки с `resolved_one_field_active`.
3. `unresolved_analytic` не распределяется по полям и остаётся отдельным QA-исключением.
4. `economic_area_ha` нельзя суммировать по строкам, операциям или датам.
5. `economic_area_ha` не равна `work_hectares`.
6. Строки `HA` и `HOURS` нельзя смешивать в одном знаменателе.
7. Нормативный ГСМ не является фактическим списанием и не имеет денежной оценки.
8. Витрина не включает ремонты, агровходы, денежный факт ГСМ и полную себестоимость.
9. Нельзя переводить почасовые работы в гектары по соседним строкам ПУЛ.
10. Нельзя называть показатели полной стоимостью работ или полной себестоимостью 1 га.

## Следующие шаги

1. Добавить витрину в DataLens с отдельным фильтром `work_volume_type`.
2. В DataLens всегда выводить `coverage_scope`, `field_link_status`, `work_measure_quality_status` и `fuel_data_status`.
3. Отдельно показывать QA-витрину и долю `unresolved_analytic`.
4. Исследовать, можно ли восстановить `pole_id` для `unresolved_analytic` через дополнительные источники 1С.
5. Проверить источник ремонтов и связать его с техникой и полем.
6. Восстановить полное денежное покрытие ГСМ.
7. После утверждения правил распределения затрат между контурами и культурами вернуться к модели полной себестоимости 1 га.
