# Лесные Дали BI — отчёт по рабочей сессии

**Тема:** DataLens / KPI6 — прямые затраты и фактическая себестоимость 1 га  
**Дата сессии:** 03 октября 2026  
**Среда:** локальный self-hosted DataLens на `vm-bi`

---

## 1. Цель сессии

Работа велась над KPI6 в BI «Лесные Дали»: подготовить DataLens-датасет и построить управленческий график **фактической себестоимости 1 га по каждому сезону**.

Под «фактом» договорились понимать зарегистрированные прямые затраты, а не сценарно дополненные значения.

**Целевой результат:** один понятный линейный чарт, где:

- ось X — сезон / год;
- ось Y — фактические прямые затраты на 1 га, ₽/га;
- значение за сезон считается как отношение суммы затрат к сумме площади по включённым строкам.

## 3. Нужный показатель

Нужен не рейтинг полей и не среднее арифметическое значений «₽/га» по отдельным полям.

Нужен агрегированный показатель по хозяйству за каждый сезон:

```text
Фактическая себестоимость 1 га за сезон
= сумма фактических прямых затрат по всем включённым полям сезона
  / сумма площадей этих же полей
```

Корректная формула в чарте DataLens:

```text
SUM([Прямые затраты, ₽])
/
SUM([Площадь, га])
```

Это взвешенный расчёт: большие и малые поля участвуют пропорционально своей площади.

### Что включать

Использовать:

```text
Прямые затраты, ₽
```

Технический смысл: `covered_registered_direct_cost_rub` — зарегистрированные прямые затраты для строк с корректным покрытием.

### Что не включать в факт-чарт

Не использовать в основном фактическом графике:

```text
Прямые затраты со сценариями, ₽
```

Это `partial_plus_scenarios_rub`: сумма, дополненная сценарными / оценочными значениями. Она может быть полезна для отдельного аналитического сценарного графика, но не должна подменять факт.

## 4. Целевая настройка чарта

### Базовый чарт

**Тип:** линейная диаграмма  
**Название:** `Фактическая себестоимость 1 га по сезонам, ₽/га`

| Настройка DataLens | Значение |
|---|---|
| Ось X | `Год` |
| Ось Y | Вычисляемая мера `Фактическая себестоимость, ₽/га` |
| Формула меры | `SUM([Прямые затраты, ₽]) / SUM([Площадь, га])` |
| Сортировка | `Год` по возрастанию |
| Цвет | Не заполнять в базовой версии: одна линия по хозяйству |
| Формат числа | `0 000 ₽/га` |
| Фильтр качества | `Статус качества данных = COVERED_REGISTERED_DIRECT_COST_ESTIMATE` |

Меру предпочтительно создать **внутри чарта** через `fx`, а не как новое вычисляемое поле Dataset до устранения ошибки поля.

### Почему нужен фильтр качества

В расчёт должны попасть только строки с полным подтверждённым покрытием:

```text
COVERED_REGISTERED_DIRECT_COST_ESTIMATE
```

Без этого фильтра в показатель попадут частичные записи с неполными затратами. Линия будет выглядеть как факт, но фактически будет занижена или несопоставима между сезонами.

### Будущее расширение

После проверки базовой линии можно добавить `Культура` в поле «Цвет», если культура доступна в датасете. Тогда на одном чарте появятся отдельные линии по культурам. Базовый управленческий чарт по хозяйству при этом должен сохраниться отдельно.

## 5. Ошибка DataLens

При работе с Dataset / предпросмотром появилась ошибка:

```text
Ошибка загрузки данных

ERR.DS_API.FIELD.NOT_FOUND
Unknown field 740660b0-bf2b-11f1-94fc-377db1deb6a2
Request-ID: dl.334c2_ck.bmqqxbd0ga
```

Это ошибка уровня DataLens API: во время исполнения запроса используется внутренний идентификатор поля, который система не может разрешить.

Рассматривались две гипотезы:

1. В сохранённых метаданных DataLens осталась ссылка на удалённое поле.
2. Возникло рассогласование Dataset / источника, процессного кэша API или состояния редактора / браузера.

### Важный вывод

На момент окончания сессии **нет доказательства**, что материализованное представление DWH отсутствует, повреждено или «упало».

Не выполнялись:

```sql
REFRESH MATERIALIZED VIEW
DROP MATERIALIZED VIEW
CREATE MATERIALIZED VIEW
```

Не следует менять DWH-витрину до появления подтверждающей ошибки со стороны внешнего источника или логов `data-api`.

## 6. Диагностика на сервере

Работа велась на сервере:

```bash
ilya@vm-bi:/data/apps/datalens$
```

### Ошибка запуска SQL

Изначально SQL-команда была введена прямо в Bash. Поэтому оболочка пыталась выполнить `SELECT`, `FROM`, `WHERE` как Linux-команды и выдала:

```text
SELECT: command not found
FROM: command not found
WHERE: command not found
```

Это не ошибка PostgreSQL. SQL надо выполнять из `psql`.

### Сервисы Docker Compose

Была выполнена команда:

```bash
docker compose ps
```

Активные сервисы:

- `datalens-postgres` — healthy;
- `datalens-data-api` — Up;
- `datalens-control-api` — Up;
- `datalens-ui` — Up, опубликован на `8088`;
- `datalens-auth`, `datalens-meta-manager`, `datalens-temporal`, `datalens-us` — Up.

В данном `docker compose` не было отдельного контейнера DWH «Лесные Дали». Следовательно:

- `datalens-postgres` — это служебный PostgreSQL DataLens;
- DWH с `mart.mv_field_season_kpi6_with_scenarios` — внешний источник подключения DataLens.

### Подключение к служебной БД

Попытка входа с ролью `postgres` завершилась сообщением:

```text
FATAL: role "postgres" does not exist
```

Это штатно для данной конфигурации: реальная роль была получена из окружения контейнера.

Рабочее подключение:

```bash
docker compose exec postgres psql -U pg-user -d pg-us-db
```

### Критичный инцидент с секретом

При выводе окружения контейнера пароль PostgreSQL был отображён в терминале и в переписке.

**Действие обязательно:** считать пароль скомпрометированным и ротировать его в конфигурации / секрете Docker Compose после завершения диагностики. Не включать пароль в документацию, git, скриншоты и дальнейшие сообщения.

`entries` содержит объекты DataLens и ссылки на актуальные сохранённые ревизии (`saved_id`, `published_id`).

### Ревизия проблемного Dataset

Для `KPI6 — прямые затраты по полям v2`:

```text
entry_id:     2317585934326957167
saved_id:     2317593044418823286
published_id: 2317593044418823286
```

### Проверка UUID поля

Проверялся UUID:

```text
740660b0-bf2b-11f1-94fc-377db1deb6a2
```

Результаты:

- поиск в `revisions.data` активной ревизии KPI6 v2 — `0 rows`;
- поиск по всем ревизиям во всех JSON-полях `data`, `meta`, `links`, `annotation` — `0 rows`.

### Вывод диагностики

Искомый UUID **не хранится** в сохранённых ревизиях мета-БД DataLens.

Наиболее вероятные направления дальнейшей проверки:

- устаревшее состояние браузерной вкладки или редактора Dataset;
- кэш/состояние процесса `data-api`;
- динамическое рассогласование набора полей при выполнении запроса к источнику;
- логика, которая передаёт внутренний field ID только во время выполнения API-запроса.

Не подтверждено, что причиной является сама МВ в DWH.

## 9. Безопасный план продолжения

### Шаг 1. Ротация раскрытого пароля

1. Сменить пароль PostgreSQL, который был показан при `docker compose exec postgres env`.
2. Обновить его в конфигурации / секрете Docker Compose.
3. Контролируемо перезапустить затронутые сервисы только после фиксации конфигурации.
4. Не вставлять новый пароль в чат, отчёты, командную историю или Git.

### Шаг 2. Чисто открыть Dataset

1. Закрыть вкладку проблемного Dataset.
2. Выполнить жёсткую перезагрузку браузера:

   ```text
   Ctrl + Shift + R
   ```

3. Либо открыть DataLens в режиме инкогнито / в другом браузере.
4. Открыть Dataset из списка коллекции, а не из ранее открытой вкладки или старой закладки.
5. Проверить, воспроизводится ли ошибка в предпросмотре.

### Шаг 3. Если ошибка сохранилась — собрать логи `data-api`

В отдельном терминале:

```bash
cd /data/apps/datalens
docker compose logs -f --tail=100 data-api
```

После запуска команды один раз открыть предпросмотр Dataset и собрать фрагмент лога вокруг ошибки.

Искать:

```text
740660b0-bf2b-11f1-94fc-377db1deb6a2
ERR.DS_API.FIELD.NOT_FOUND
dl.334c2_ck.bmqqxbd0ga
```

Перед передачей логов скрыть:

- пароли;
- `Authorization`;
- cookies;
- токены;
- connection string с паролем.

### Шаг 4. Создать основной чарт после восстановления Dataset

Создать в чарте через `fx` меру:

```text
Название: Фактическая себестоимость, ₽/га

SUM([Прямые затраты, ₽])
/
SUM([Площадь, га])
```

Настроить линейную диаграмму:

```text
X: Год
Y: Фактическая себестоимость, ₽/га
Фильтр: Статус качества данных = COVERED_REGISTERED_DIRECT_COST_ESTIMATE
Сортировка: Год по возрастанию
```

### Шаг 5. Контроль цифр

После построения графика проверить минимум один сезон прямым SQL-запросом к DWH:

- сумма `covered_registered_direct_cost_rub`;
- сумма `stable_economic_area_ha`;
- их отношение;
- совпадение с точкой на чарте.

## 11. Итог

Главная бизнес-задача зафиксирована: требуется **сезонный график фактической себестоимости 1 га**, а не таблица полей и не топ затрат.

Правильная мера:

```text
SUM([Прямые затраты, ₽]) / SUM([Площадь, га])
```

Её нужно использовать только для строк с полным качественным покрытием:

```text
Статус качества данных = COVERED_REGISTERED_DIRECT_COST_ESTIMATE
```

Ошибка `FIELD.NOT_FOUND` локализована как ошибка разрешения внутреннего поля DataLens. По выполненной проверке она не доказала поломку DWH-витрины и не потребовала опасных изменений в БД. Следующий технический шаг — чисто воспроизвести ошибку и при необходимости собрать логи `data-api` во время запроса.
