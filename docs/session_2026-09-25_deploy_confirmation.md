## Ремонт техники (`mart.fact_equipment_repair_cost`) — закрыто статусом "нет данных"

Исследовано 25.09.2026. Изначальная гипотеза из аудита 17.09 (баг JOIN на
`e.ref_key_1c` вместо `dim_equipment.code_1c`) оказалась нерелевантной: FK
`fact_equipment_repair_cost_equipment_sk_fkey` уже корректно ссылается на
`dim_equipment.eq_sk`.

Реальная причина 0 строк — отсутствие исходных данных:

```text
raw.r1c_equipment_repair:        3 документа, из них 1 проведён
  (_id = b77c2105-2eb1-11f1-b81f-005056bde474)
raw.r1c_equipment_repair_works:  1 строка на всю таблицу,
  но её doc_id НЕ совпадает с _id проведённого документа
staging.v_equipment_repair_clean: 0 строк (подтверждено запросом)
```

Источник проблемы — OData-выгрузка табличной части "Работы" документов ремонта,
не SQL-код в `files/23_raw_equipment_repair.sql`. Исправление кода витрины ничего не
даст, так как в raw физически нет связанных строк работ для проведённых документов.

**Решение:** не тратить время на фикс JOIN. Закрыть как "нет данных в 1С /
требуется проверка OData-выгрузки", не в этой сессии. Финансовый эффект в
любом случае ограничен — 1 документ на всю историю компании.

Следующий шаг (если будет время): проверить в $metadata OData 1С, как
называется entity set табличной части "Работы" в `Document_АпкВыполнениеРемонтаТС`
и почему текущий запрос её не выгрузил (возможно, аналогичная проблема $select,
что и с табличной частью "Товары" в актах списания).
