# LesDaliBI — экономическая площадь поля на дату

- **Дата сессии:** 2026-09-24
- **Репозиторий:** `SexyIdol2003/LesDaliBI`
- **SQL-коммит:** `232914b feat(dwh): add date-based economic field area mart`
- **Статус:** витрина создана, применена в PostgreSQL и проверена QA.

## Цель

Найти методологически корректный знаменатель площади для будущей модели полевой экономики и KPI затрат на гектар.

Исходное ограничение проекта:

> Нельзя публиковать полную себестоимость 1 га, пока в расчёте нет единой экономической площади, полного денежного покрытия ГСМ и источника ремонтов техники.

В ходе проверки была исследована история полей из 1С и создана изолированная витрина экономической площади **на конкретную дату**.

## Источник площади

Источник:

```sql
raw.r1c_polya_istoriya
```

Ключевые поля:

| Поле | Назначение |
|---|---|
| `pole_id` | Идентификатор поля 1С |
| `kultura_id` | Идентификатор культуры / сорта |
| `ploshad_obshaya` | Общая площадь контура, га |
| `ploshad_seva` | Площадь сева, га |
| `nachalo_perioda` | Начало периода актуальности контура |
| `konec_perioda` | Конец периода актуальности контура |
| `eto_roditel` | Признак родительской / сводной строки |
| `ne_ispolzuetsya` | Признак неиспользуемой строки |
| `god_urozhaya` | Год урожая из источника |

### Наблюдение по данным

В детальных дочерних строках истории `god_urozhaya` часто имеет значение `0`, хотя даты периода актуальности относятся к реальному календарному году.

Пример: у поля `318` активные детальные контуры имеют периоды 2026 года, но `god_urozhaya = 0`.

Поэтому сезон для витрины экономической площади определяется из `snapshot_date`, а не из `god_urozhaya`.

## Почему нельзя использовать одну площадь на год

Для одного поля одновременно могут быть активны несколько контуров и культур.

Пример поля `318`:

| Контрольная дата | Активных контуров | Активных культур | Экономическая площадь, га | Максимальный отдельный контур, га |
|---|---:|---:|---:|---:|
| 2026-01-15 | 2 | 2 | 98,84 | 65,04 |
| 2026-03-15 | 2 | 2 | 98,84 | 65,04 |
| 2026-05-01 | 8 | 8 | 465,04 | 148,00 |
| 2026-05-15 | 8 | 8 | 465,04 | 148,00 |
| 2026-06-15 | 8 | 8 | 465,04 | 148,00 |
| 2026-10-15 | 8 | 8 | 465,04 | 148,00 |
| 2026-11-15 | 2 | 2 | 98,84 | 65,04 |

Следствия:

1. `MAX(area_ha)` выбирает лишь крупнейший контур и не отражает полную активную площадь поля.
2. Простая `SUM(area_ha)` по всем строкам года также неверна: разные контуры имеют разные периоды актуальности, а часть из них сменяет друг друга внутри года.
3. Корректна только сумма контуров, которые одновременно активны на дату конкретного документа или операции.

## Методика расчёта

Экономическая площадь на дату рассчитывается так:

```text
economic_area_ha =
SUM(ploshad_obshaya)
```

В расчёт включаются только строки истории полей, для которых:

```text
eto_roditel = false
ne_ispolzuetsya = false
ploshad_obshaya > 0
snapshot_date BETWEEN nachalo_perioda AND konec_perioda
```

Источник поля:

```text
raw.r1c_polya_istoriya.ploshad_obshaya
```

Метод:

```text
ACTIVE_CONTOURS_SUM_ON_DATE
```

Статусы качества:

```text
OK_SINGLE_ACTIVE_CONTOUR
OK_MULTIPLE_ACTIVE_CONTOURS_SUMMED
NO_ACTIVE_AREA
CHECK_AREA
```

## Как использовать

Допустимое применение:

- контроль актуальной площади поля на дату документа;
- расчёт агровходов на экономический гектар на уровне документа или даты;
- распределение документных затрат между активными контурами по утверждённому правилу;
- QA истории полей, состава контуров и культур;
- подготовка будущей модели `поле × дата × культура`.

Не допускается без отдельной методики:

- суммировать `economic_area_ha` по датам;
- усреднять дневную площадь для получения сезонного знаменателя;
- применять витрину к 2021–2025 годам;
- считать полную себестоимость 1 га;
- объединять агровходы, зарплату, ГСМ и ремонты в единый показатель без правил распределения и статусов полноты.

## Ограничения

1. Витрина построена только для 2026 года.
2. В детальных строках истории `god_urozhaya` ненадёжен как самостоятельный ключ сезона.
3. Для исторических агровходов 2021–2025 текущая связка с историей полей не подтверждена.
4. Витрина не содержит денежную оценку ГСМ, ремонты, зарплату и другие компоненты полной себестоимости.
5. При нескольких активных культурах затраты пока не распределяются между культурами автоматически.
6. Родительские и сводные строки истории полей исключаются из расчёта.
7. Полевая площадь на дату является экономической базой для дальнейшего анализа, но не подтверждает автоматическое отнесение каждого расхода на конкретную культуру.

## Следующие шаги

1. Проверить покрытие экономической площадью на дату строк ПУЛ, зарплаты и распределённого факта ГСМ.
2. Определить метод распределения затрат поля между активными контурами и культурами: пропорционально площади, прямое отнесение при наличии культуры в документе либо отдельный статус для расчётного распределения.
3. Проверить возможность расчёта сезонной экономической площади без суммирования ежедневных значений.
4. Восстановить полную денежную оценку ГСМ.
5. Подключить источник ремонтов техники.
6. Только после утверждения площади, ГСМ, ремонтов и правил распределения проектировать KPI полной себестоимости 1 га.
