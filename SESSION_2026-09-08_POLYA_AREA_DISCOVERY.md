# Сессия 2026-09-08 — площадь поля и витрина урожайности (итоговая версия)

Репозиторий: https://github.com/SexyIdol2003/LesDaliBI

## Результат сессии

Закрыт блокер, который держал проект с 19 августа: **площадь поля теперь грузится из 1С и связана с фактом урожая**. Витрина `mart.v_fact_harvest_yield` возвращает реалистичные значения урожайности картофеля (большинство полей в диапазоне 10–38 т/га) по полю/году.

## Контекст

С 2026-08-19 было известно, что `raw.r1c_polya.area_ha` пусто во всех 48 полях — это блокировало расчёт урожайности (т/га) и себестоимости на гектар. Раньше (STATUS_2026-08-13) `Catalog_АпкПоля` вообще возвращал `odata.error code:20 "Доступ запрещён"`.

## Цепочка из пяти последовательных багов в одной табличной части

Все ошибки обнаружены на живом примере поля №318 (`Ref_Key d7ca999f-f153-11eb-9c3a-00505689ff45`), через итерации запуска DAG и разбора реальных данных.

### 1. Права на `Catalog_АпкПоля` открыты
Сущность отвечает нормально (нет 404/"Доступ запрещён"), в отличие от 13 августа.

### 2. Площадь не существует как плоское поле
Предположение `АпкПлощадьПоляГа` из старого DAG было неверным (404). Реальная площадь хранится в табличной части **`ИсторияПоля`** — по одной строке на контур/культуру/период на поле, с полем `ПлощадьОбщая`.

### 3. `$expand` для табличных частей не работает (HTTP 501)
Точно так же, как с табличной частью ГСМ в заправочных ведомостях (SESSION_2026-09-07). Фикс: табличная часть запрашивается как обычное поле в `$select` — она приходит инлайн.

### 4. Даты периода иногда перепутаны
`НачалоПериодаАктуальности` иногда позже `КонецПериодаАктуальности` (например, начало 2021-01-01, конец 2020-12-31). Фикс: сравнение через `LEAST`/`GREATEST` вместо простого `BETWEEN`.

### 5. Признак `ЭтоРодитель` имеет обратный смысл
- `ЭтоРодитель = true` — служебная строка-заголовок года: площадь=0, даты-заглушка `0001-01-01`.
- `ЭтоРодитель = false` — РЕАЛЬНЫЕ строки с площадью и реальными датами.

Надо было брать `eto_roditel = false`, а не `true`, как казалось интуитивно по названию поля.

### 6. `НеИспользуется` мечен на всей истории, а не только на неактуальных
Этот флаг означает "эта историческая запись больше не актуальна" (ср. текст "318, Пар 2020 г. (не исп. с 31.12.2020)") — поэтому он ставится `true` У ВСЕХ прошлых периодов, а не только у действительно отменённых. Фильтр по нему вырезал всю историю — убран из витрины.

### 7. Одно поле разбито на несколько контуров одновременно
В один и тот же период поле может быть разбито на несколько контуров с разными культурами (у поля 318 в 2023 году — 10 разных культур). Джойн по дате даёт несколько строк на поле-год — нужно суммировать площадь всех подходящих контуров, а не делить весь урожай поля на площадь одного случайного контура (иначе получались абсурдные 1000+ т/га).

## Созданные объекты

### DAG
`files/airflow/dags/dag_extract_polya_istoriya.py` — ежедневно в 01:15 грузит `Catalog_АпкПоля` с табличной частью `ИсторияПоля` в две таблицы: `raw.r1c_polya` (справочник) и `raw.r1c_polya_istoriya` (история площадей, включая `eto_roditel`/`eto_vetv`).

### SQL / витрины (`files/20_raw_polya_istoriya.sql`, `files/21_harvest_area_yield.sql`)
- `raw.r1c_polya_istoriya` — история площадей по годам/культурам/контурам.
- `mart.v_field_area_by_date` — чистая площадь поля на дату (одна строка = один контур), без служебных строк-заголовков.
- `mart.v_fact_harvest_yield` — финальная витрина: поле + год + суммарный вес урожая (из `mart.v_fact_harvest_tok`) + суммарная площадь всех контуров, действующих на дату первого взвешивания в году + `yield_t_ha`.
