## Зачем этот файл

Предыдущие сессионные MD-файлы фиксировали, ЧТО было сделано, но статус
показателей 1, 2, 3, 4, 6 записывался как обобщённая заглушка

продолжать с того места, где остановились. Этот файл — первая попытка

17.09.2026, а не предположения из кода.

## Issue #2 (закрыт, not_planned) — критическое ограничение для показателя №2

`mart.fact_putevoy_rabota.pole_id` всегда NULL. Расследование
15.09.2026 показало: `КлючСвязи` в путевом листе — это внутренняя
связь между табличными частями одного документа (работа ↔ техника),
а НЕ ссылка на поле. Табличная часть `Задание`, где теоретически
могла быть привязка к полю, физически пуста во всей базе 1С (проверено
на 5 документах и глобальным запросом). Это ограничение бизнес-процесса
заказчика — механизаторы не указывают поле в путевом листе, а не баг
DAG или ETL.

**Следствие:** затраты на технику по конкретному полю через путевые
листы построить нельзя. Показатель №2 в разрезе "поле" нужно строить
через другие источники, где `Поле_Key` реально есть:
`raw.r1c_dvizhenie_produkcii_lines`, `raw.r1c_tok_vzveshivanie_talony`,
`raw.r1c_polya_istoriya`, либо использовать `fact_putevoy_rabota` только
в разрезе техника/операция/период (без поля) — так же, как сделан
показатель №5 через `v_fact_equipment_costs_by_period`.

## Правильная связка "поле" (важно для показателей №1, №2, №3)

`raw.r1c_fields` — пуст, использовать нельзя, PK там `_id`, не `ref_key`.

Реальный работающий справочник — **`raw.r1c_polya`** (описание поля =
номер поля в виде текста). Связка делается НЕ по GUID, а через функцию
`staging.extract_field_number_any(text)`, которая вытаскивает номер
поля из свободного текста документа (например, "поле 318"), и матчится
на `raw.r1c_polya.description`. Именно так работает показатель №1
(урожай, через `raw.r1c_tok_vzveshivanie` + прямую связь
`Талоны.Поле_Key`, подтверждено 100% покрытием 2021-2025).

Для показателя №3 (`raw.r1c_field_material_writeoff_doc.apk_obekt_zatrat_id`,
тип UUID) нужно сначала выяснить, что это физически — GUID поля из
`Catalog_АпкПоля`, либо GUID какого-то другого "объекта затрат". Через
`raw.r1c_fields`/`raw.r1c_polya` напрямую по GUID не проверено —
следующий шаг.
