## Что подключили к DataLens (датасеты и чарты)

### Датасет 1 — «ГСМ: план-факт по операциям» (`mart.fact_fuel_plan_fact_by_operation_confirmed`)
Создано вычисляемое поле **«Отклонение % (агрегир.)»**:
```
(SUM([Факт ГСМ, л]) - SUM([Норма ГСМ, л])) / SUM([Норма ГСМ, л]) * 100
```
Причина: сырое поле `variance_pct` считалось построчно и при усреднении на графике давало аномальные выбросы (до +17000% на отдельных строках с почти нулевой нормой).

Чарты (добавлены в дашборд **«Полевые работы — техника и выработка»**):
- ГСМ: план-факт по операциям (комбо-чарт)
- ГСМ: план-факт по операциям — Сводная таблица
- Отклонение по операциям, %
- Расход ГСМ на 1 га по технике

### Датасет 2 — «Затраты на удобрения и СЗР на га» (`mart.v_agro_input_cost_per_field_season`)
Чарты (добавлены в дашборд **«Полеводство — урожай картофеля»**):
- Расход на агрохимию на 1 га по полям
- Затраты на удобрения и СЗР на га — Таблица

**Ограничение: только сезон 2026** (см. раздел "Известные проблемы").

### Датасет 3 — «Урожайность по сортам» (`mart.v_fact_harvest_yield_by_variety_ready`)
Новая view создана в БД в рамках сессии:
```sql
CREATE OR REPLACE VIEW mart.v_fact_harvest_yield_by_variety_ready AS
SELECT * FROM mart.v_fact_harvest_yield_by_variety
WHERE yield_t_ha IS NOT NULL;

GRANT SELECT ON mart.v_fact_harvest_yield_by_variety_ready TO datalens_ro;
```
Причина: исходная `v_fact_harvest_yield_by_variety` (74 строки) содержала NULL по `yield_t_ha` в 36 строках из-за отсутствия площади по сорту за некоторые годы.

Чарт (добавлен в дашборд **«Полеводство — урожай картофеля»**):

**Известный баг на момент конца сессии:** в чарте вычисляемое поле «Затраты всего, руб» было ошибочно добавлено в стек вместе с исходными компонентами (задвоение). Исправление: убрать «Затраты всего, руб» из Y, оставить три исходных меры (Зарплата работа / Зарплата ремонт / Затраты на ГСМ) — DataLens сам посчитает сумму в тултипе. **Нужно проверить, что фикс применён.**

## Известные проблемы и задачи на следующую сессию

### Задача 1 — Показатель 3: расход на агрохимию только за 2026 год
**Причина (подтверждена диагностикой в psql):** количество/площадь по агроматериалам (`mart.fact_agro_input_usage`) выгружены за несколько лет (минимум с 2021), но **закупочные цены** (`raw.r1c_purchase_lines_2026`) выгружены из 1С **только за 2026 год** — колонка `cost_rub_per_ha` в `fact_agro_input_usage` физически пустая для строк раньше 2026.

**Что нужно сделать:**
1. Доработать DAG экстракции 1С — тянуть документы поступления/закупки (`Document_ПоступлениеТоваровУслуг` или аналог АПК) без ограничения по дате, за весь период 2021–2026.
2. Загрузить историю закупок в raw-слой (расширить или заменить `r1c_purchase_lines_2026` на многолетнюю версию без суффикса года).
3. Применить уже написанную логику подбора цены («последняя закупка до списания» / «первая после списания») на всей истории.
4. Заполнить `cost_rub_per_ha` в `fact_agro_input_usage` за все годы.
5. Пересобрать `v_agro_input_cost_per_field_season` (или сделать новую версию без суффикса "_2026") на всех годах.

### Задача 2 — Показатель 4: нет урожайности по сорту за 2023-2024
**Причина:** в `mart.v_field_area_by_variety` за 2023-2024 годы по проблемным полям есть только записи "Пар под картофель_20XX" (без указания конкретного сорта), а не полноценные декларации площади по сорту, как за 2021/2022/2025/2026.

**Что нужно сделать:** уточнить у агрономов/владельца 1С, заводились ли в принципе документы площади по сорту за 2023-2024, и если да — найти правильный источник в 1С (возможно, другой тип документа) и перегрузить.

### Задача 3 — Показатель 6: себестоимость 1 га за сезон не собрать
**Причина:** `mart.v_fact_equipment_costs_by_period` считает затраты на технику только в разрезе «техника × месяц», без привязки к конкретному полю. Связка «техника → поле» физически не ведётся в 1С на уровне путевого листа (см. Issue #2 в GitHub, закрыт как `not_planned`: `fact_putevoy_rabota.pole_id` всегда NULL).

**Что нужно сделать:** искать альтернативный способ распределения затрат на технику по полям — например, через гектары обработки по документам полевых работ (не через путевые листы), либо принять, что показатель 6 останется только на уровне «хозяйство в целом», без разбивки по полям.

### Задача 4 — проверить фикс задвоения в чарте «Затраты на технику за период»
Убедиться, что вычисляемое поле «Затраты всего, руб» убрано из стека Y и не дублирует зарплату/ГСМ (см. раздел "Датасет 4" выше).
